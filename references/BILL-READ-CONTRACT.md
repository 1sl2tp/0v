# L08 read-only bill projection — backend review proposal
Observed 26/11/2026: public.v0_admin_media(uuid) invokes private admin_media, checks active admin session and eligible conversation membership, returns at most latest 100 messages' assets. public.chat_bank_bill_receipts has media_asset_id, message_id, customer_account_id, raw_read, amount_vnd, receiving_account/name, transfer_at_vn, sending/receiving_bank, transfer_reference, status, ledger_id. No client-side table grant/policy should be added.
Proposed: extend authorized existing v0_private.admin_media SELECT only; do not alter its auth checks, scope, grants, storage policy or data. Within existing select of a.* use a LEFT JOIN LATERAL selecting one receipt by r.media_asset_id=a.id AND r.message_id=a.message_id AND r.customer_account_id=a.owner_account_id. If multiple rows exist, select latest scanned_at DESC NULLS LAST, created_at DESC, id DESC; verify uniqueness before rollout. For non_bill return null or non_bill. Return bill_receipt as a JSON object with asset_id, message_id, status, has_ledger (ledger_id IS NOT NULL; verify referenced ledger semantics before release), amount_vnd as decimal string, date_vn/time_vn from explicitly printed/validated date/time evidence (do not substitute message sent time or assume midnight if absent), receiving_account, receiving_name, transfer_content (only if jsonb_typeof(raw_read->'transfer_content')='string'), transfer_reference, sending_bank, receiving_bank. Missing values null. Never return raw_read, receipt IDs, ledger ID, image hash, model details or other customers' data.
Tests: unauthenticated/nonadmin/foreign room/locked contact denied; correct asset and message only; wrong asset/message/customer cannot attach; absent record and non_bill keep ordinary gallery; received without ledger never says collected; missing time stays missing; no writes or external side effects. Validate function in isolated DB and review exact SQL before production rollout. No migration applied by this PR; existing API unchanged.

## SQL candidate / isolated gate
`0v-admin-media-bill.sql` preserves the existing private function signature, owner, grants and admin/contact checks. Existing `media_asset_id` UNIQUE and ledger FK verified; ledger must belong to same customer and entry_type collection. No amount comparison across differing units. Receipt fields additionally require AAL2, without changing AAL1 ordinary media access. Date/time are shown only when printed evidence and canonical timestamp agree and conflict flags do not reject them; old receipts lacking printed evidence stay missing. No raw JSON or ledger ID returned. `fixtures/bank-db/bill-read-test.sql` uses synthetic auth/session tables and actual repository admin_read SQL, with tests for correct/mismatched identity, ledger, time, foreign room, nonadmin, absent session, locked contact and AAL1. Runs in the existing isolated PostgreSQL CI service. This branch is intentionally outside automatic UI release gate; deployment requires CI success and separate schema review; no UI version bump or production DDL in this step.
